# 1.3.0：语义样式、品牌主题与 Compose 内容

状态：1.3.0 已于 2026-11-10 正式发布，三个模块的公开仓库与独立消费者已验收，结果见 [发布记录](../releases/1.3.0.md)。本文保留各阶段设计与历史验收；后文“本轮未执行”仅描述对应阶段。源码与 CI 验证继续显式使用 `1.3.0-SNAPSHOT`。

## 目标与依据

本版让 View、Java、LifecycleOwner 与 Compose 使用者共享语义提示和可复用品牌样式，同时保护 1.2.0 的串行队列、容量、过期、取消及页面归属契约。

借鉴 [Toasty](https://github.com/GrenderG/Toasty) 的语义调用、[StyleableToast](https://github.com/Muddz/StyleableToast) 的资源样式、[MotionToast](https://github.com/Spikeysanju/MotionToast) 的成套视觉，以及 [Compose Snackbar](https://developer.android.com/reference/kotlin/androidx/compose/material3/SnackbarHostState) 的请求与展示分离。独立实现代码和矢量图标，不复制第三方源码或资源。竞品文档不作为性能、维护状态或 Android 兼容认证。

## 语义与资源样式

- 新增 `KToastType`：NORMAL、SUCCESS、ERROR、WARNING、INFO；类型只影响视觉，不隐式改变队列、时长或去重。
- 不可变 `KToastStyle(type, styleRes)` 不持有 Context/View；`resolve(context, baseConfig)` 返回副本，可用于独立预览。
- 全局、Activity、LifecycleOwner 和 Compose wrapper 均提供 `showStyled`，返回原 `ToastHandle`；Java 可用明确重载。
- 覆盖顺序：基础配置 → 启用的宿主主题 → 语义 → 品牌 XML → 单次 DSL。旧普通入口不读取新样式，保持原规则。
- 样式在获得准入额度后解析，拒绝请求不解析资源或执行 DSL。配置副本在提交时固定；资源/主题及 DSL 在调用线程准备，渲染与回调在主线程。调用方不得并发修改主题。
- XML 使用 `kToast*` 前缀视觉属性，支持 `values-night`、显式隐藏图标及主题引用；dimension 按既有 dp/sp/px 约定转换，TypedArray 始终回收。
- 不修改已发布 `KToastConfig` 等 data class 主构造、默认参数与 copy 的 JVM 形态。

## Compose 扩展

独立模块 `library-compose`，正式坐标 `io.github.logan0817:ktoast-compose:1.3.0`，传递同版 `ktoast-lifecycle` 与核心。核心及生命周期单独接入不增加 Compose/Material/协程依赖。

`rememberKToastScope` 在 Composition 提交后绑定真实 ComponentActivity、LocalLifecycleOwner、LocalSavedStateRegistryOwner 与父 Composition。普通重组复用作用域，绑定对象或 options 改变时关闭旧入口。停止取消旧活动期，恢复只接受新请求；离开 Composition、Owner 销毁或 close 永久关闭。关闭后的新调用明确抛异常，已提交句柄继续按核心契约取消。

`showContent` 在请求实际展示时创建 ComposeView，复用唯一调度器、窗口几何及现有句柄；不叠加另一套 HostState/Mutex 队列。description 必须非空白，作为消息、去重依据与窗口无障碍描述。终态和窗口脱离释放内容、父 Composition 与 ViewTree owner。`KToastContent` 不显示窗口，可独立 Preview；Preview 中作用域不执行真实绑定。

技术验证发现 ComposeView 的首次用户组合可能发生在异步 attach 阶段，工厂返回不能保证用户内容已经执行。因此：工厂创建/同步挂载错误走核心错误路径；用户 Composable 内部异常（包括首次及后续重组）遵循应用 Compose 异常机制，不承诺将其转换为取消或成功，不自行吞异常。

依赖基线：Kotlin 1.9.23 + Compose compiler 1.5.13，Compose Runtime/UI/Foundation 1.7.8、Lifecycle Runtime Compose 2.8.3、Activity 1.9.2、SavedState 1.2.1；minSdk 21、JVM 1.8。库不依赖 Material。实际最低兼容结果由独立消费者、AAR/metadata 与运行验证确认。

## 动画插值器与裁剪

保留默认缩放回弹。前台全局入口和页面入口均使用透明动画容器，为放大峰值及阴影预留窗口空间；页面窗口整体仍受安全区域和最大宽度约束。新增不可变 `KToastAnimation(enterInterpolator, exitInterpolator, maxScale)`，通过 `KToastConfig.animation` 全局继承或单次覆盖，Lifecycle 和 Compose 共用。插值器为 null 时使用原有默认回弹；`maxScale` 默认 1.05，允许有限的 1～2，实际缩放限制在预留空间内。后台系统 Toast 仍使用系统动画。

为保持旧主构造、copy/default JVM 形态，animation 是类体属性；新增 snapshot() 进行完整复制，库内部的全局继承、样式解析和提交快照均使用它。Kotlin 自动生成的 copy/equals/hashCode 仍只涉及既有主构造属性。插值器在主线程执行，必须返回有限值，提交后不能修改其内部状态。用法与复制边界见 [USAGE](../USAGE.md#动画插值器130)。

## 范围与回退

本版不增加无限 loading、原位更新、业务任务执行器、多条堆叠、全局 Flow 总线、复杂手势、动态策略切换或多窗口并行调度。原位更新后续单独定义期限、终态、更新失败、去重和系统降级契约。

旧应用不使用新入口时无需迁移。新增模块停止依赖后可恢复原页面作用域；核心与扩展必须同版。已发布版本不覆盖重发；发现回归使用新补丁版本，消费方成套回退到经过验证的模块组合。
